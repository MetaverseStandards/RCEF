# Governance and release gates

Original documentation: CC-BY-SA-4.0.

Repository ownership follows its actual GitHub owner. Maintainer and semantic reviewer assignments are project decisions; this document does not invent a standards mandate or external approval.

Proposals identify the problem, public evidence, compatibility impact, alternatives, tests and unresolved questions. Stable signal IDs survive label edits; retired IDs require documented tombstones. Schema, operator and data versions change independently. Changes affecting semantics or licenses require review before publication.

A data release requires complete selected inventories and disposition coverage, valid evidence references, deterministic packs, checksums and passing consumer tests. Unresolved evidence may be released as inventory when clearly labeled; affected executable rules remain unavailable. A release states its tested shared tooling commit and actual Python versions.

Review runtime behavior independently from taxonomy. Device support, rig deformation, VRM composition, Roblox certification and standards adoption require their own measured acceptance. An exact scalar rule certifies its declared operation within assumptions.

Before publishing, check the intended visibility, source provenance, inherited notices, generated bytes, dependency pin, tests, documentation links and history. RCEF begins private; making it public is a separate visibility decision.
