Seven handoffs

Architecture and ownership

Discovery, validation and pack compilation lead to separate runtime and artifact-export paths. Mapping receives an in-memory Pack; the map/evaluate CLI rebuilds it from TOML. Readable reports consume generated pack JSON directly.

RCEF supplies

Facts, rules and review surfaces

Pack metadata, provider and canonical signals, profiles, evidence, directional mappings and original numerical fixtures. RCEF’s launcher delegates the shared check, then runs its presentation exporter. Consumer tests live in tests.

MSF implements

Parsing, compilation and runtime

Authoring discovery and strict validation, pack compilation, mapping compilation/evaluation, and separately glTF/GLB inspection and sidecar binding. Runtime diagnostics/loss reports are distinct from readable presentation reports.

Interactive reference

Explore a stage or file role

Folders organize authoring; parsed top-level keys determine record kinds. Stage selection explains the handoff. Role selection filters the complete authoritative file list; it does not change parser behavior.

1 · Discover TOML, then merge arrays

A directory must contain pack.toml. MSF recursively discovers lowercase .toml, prunes hidden names and generated, rejects visited symlinks, and sorts paths globally. Arrays are appended; repeated metadata keys refuse. A single TOML input must contain the complete document.

Source: load_authoring / _authoring_files and _scan_directory. Portable path collision checks and resource limits apply.

2 · Strict parsing, schema and references

Bounded preflight and strict UTF-8 feed tomllib.loads. The actual validator enforces known keys, required fields, scalar domains, enums, unique IDs and exact references. TOML syntax validity alone does not admit a pack. Inventory can preserve well-formed unresolved entries.

Source: _toml_document and validate_authoring / validate_signal / validate_rule.

3 · Compile the validated document

compile_pack accepts an admitted ValidatedAuthoring, not a raw dictionary. The Pack contains the same validated document, held immutably, with canonical-byte SHA-256. This stage does not compile a rule graph or bind an asset.

Source: compile_pack / Pack.

4 · Render and check deterministic bytes

MSF renders rcef.pack.json, rcef_mapping.csv, coverage.json and SHA256SUMS. The CSV is a signal/profile membership matrix. Default check compares bytes; --write regenerates. Unexpected generated entries can fail the shared check.

Source: _check_inside. Individual replacements are atomic; the output set is not one transaction.

5 · Compile a chosen mapping and evaluate frames

Select a mapping, an in-memory Pack and explicit source/target typed snapshots. The map/evaluate CLI builds that Pack from TOML rather than reading generated files. Compilation checks graph, endpoint type/domain/calibration/evidence and approximation policy. Evaluation requires exact frame objects with nonnegative seconds, finite in-domain scalar values and explicit boolean validity. Any error yields no evaluated Result value.

Source: profile_snapshot / compile_mapping / evaluate_mapping. No clamping, neutral substitution or implicit cross-provider conversion.

6 · Present authored facts directly from the pack

RCEF exports inventory, mapping and canonical-correspondence Markdown/CSV pairs. It includes unresolved and excluded records. A dash means no authored rule. Markdown reports bind the consumed pack bytes; reports/SHA256SUMS binds the six presentation files.

Source: render / export. This exporter does not call the scalar evaluator or generate geometry.

7 · Independently check correctness and scope

Run the drift check and the tests using reviewed tools. Native backend tests, package admission, capture validity and physiological calibration remain distinct.

Source: tests and contribution workflow. No fresh test result is claimed here.

Actual schema · no inferred keys

Authoring TOML correctly

The complete metadata in pack.toml

schema_version = "1.0"
data_version = "0.1.1"
operator_version = "1.0"
id = "rcef.parity"
license = "CC-BY-SA-4.0"

There is no fragment file-list key. Directory loading supplies the four merged arrays: signals, profiles, mappings, evidence. A complete single-file input must supply them itself.

Schema and operator version accept only “1.0”. Data version is independently versioned, with the validator’s three-number semantic-version spelling and optional prerelease suffix.

Arrays and nested tables mean different things

[[signals]] appends a record; [signals] creates an object and fails the array requirement. domain = { min = 0.0, max = 1.0 } is an inline nested object.

[signals.domain] describes the latest signal’s domain. Put the signal’s own fields before opening nested tables. rules = [{...}, {...}] and repeated [[mappings.rules]] are array spellings; [mappings.rules.operator] is the latest rule’s nested operator object.

Dots in keys create nesting. Dots in an ID string are literal: "arkit.coefficient.eyeBlinkLeft" is one exact ID.

References are exact and case sensitive. IDs remain unchanged, without trimming or normalization. IDs are unique within each category; rule IDs are unique across mappings. Profile memberships, rule endpoints and evidence references must resolve. Names, labels, sides or anatomical resemblance never create aliases or mappings.

Types, status and order that matter while editing
  • Dispositions are mapped / unsupported / unresolved / excluded; evidence statuses are verified_current / proposed / unresolved. Status, disposition and rule quality answer separate questions.
  • Units and calibration are required nonblank strings. Neutral and native default are independently optional finite values within domain. Neither is a fallback.
  • Validity is a boolean or nonblank description; confidence is a nonblank description or number in [0,1]; time is a description. Coupling is a description or array of unique descriptions. These authoring descriptions do not execute.
  • Opaque inventory details belong in metadata. Unknown structural keys, duplicate reference-array entries and dangling references fail.
  • Global fragment order and each array’s order are preserved. JSON sorts object keys, not arrays. Profile columns follow profile order; weighted-sum weights follow input order. Compilation repeatedly appends all currently dependency-ready rules in authored order. Dependencies execute first; authored order is preserved within each ready batch. Independent rules in different batches may change relative order.
  • Strict TOML parsing is followed by JSON-compatibility and numeric checks. TOML dates/times, boolean scalars, NaN and infinity do not create valid scalar data. Text is never executed.
  • A new lowercase TOML file anywhere in the discovered tree participates, including a future example under docs/. Keep examples in documentation code fences or outside the authoring tree.

Exact definitions: SIGNAL_REQUIRED / SIGNAL_OPTIONAL, validate_signal, validate_rule and validate_authoring. Full field tables and source excerpts: Markdown guide.

Separate declarations from samples

Runtime admission and raw validity

Inventory validation is a wider scope

A well-formed unresolved record can be preserved in a pack. A requested mapping needs mapped participating rules/signals, nonempty own evidence and compatible endpoint type, units, domain and calibration. Current rules need current endpoints; proposed rules may use current/proposed endpoints. Current records need current references; proposed records may use current/proposed references. Unresolved participants refuse.

Identity also requires matching presence/value of neutral, side and coupling. Nonidentity rules require nonempty derivation assumptions when calibration/units differ, mapping_quality is approximate, or a loss effect is approximated, dropped or unknown. Declared approximation/loss opt-in is checked separately for all operators. Multiple writers, competing source drivers, cycles and absent terminal target channels refuse. Compilation repeatedly appends all currently dependency-ready rules in authored order. Dependencies execute first; authored order is preserved within each ready batch. Independent rules in different batches may change relative order.

The unresolved MediaPipe→ARKit blink rule remains an inventoried ambiguity. Its identity operator spelling does not admit execution. Approximation opt-in does not bypass evidence/type checks.

Every actual frame supplies validity

Frames contain exactly timestamp, values, validity. Timestamp is nonnegative finite seconds. Every supplied scalar has a corresponding boolean validity, and every mapping-required external input must be supplied.

  • Missing validity: E_VALIDITY.
  • Required value and validity both absent: E_MISSING_SAMPLE.
  • Finite in-domain value with validity false: E_INVALID_SAMPLE, even when the number equals neutral.
  • Unknown/non-source channel: E_SAMPLE_REFERENCE.
  • Nonfinite, boolean or out-of-domain values refuse; values are checked before/after each operator.

Any frame error gives the entire Result no evaluated value. Valid frames preserve input order and output validity true. There is no smoothing, neutral/default substitution or hidden resampling.

Authoring mapping and asset binding are separate operations

profile_snapshot(pack,id) supplies virtual typed channels. A rule links signal IDs by scalar arithmetic. Asset binding separately connects a signal to a structural glTF/GLB mesh-instance morph target; names alone never bind geometry.

binding fields: id, value_type, units, domain, calibration, ref
ref fields: asset_sha256, locator, node, mesh, target
optional ref field: resource_sha256
locator must agree with /nodes/{node}/weights/{target}
sidecar: schema_version, asset_sha256, resource_hashes, bindings
optional sidecar field: metadata

Sidecar reuse verifies exact source and consumed-resource hashes, indices and locator agreement. annotate_asset writes a sidecar, preserving asset bytes. Asset-based CLI mapping requires explicit sidecars; profile-based fixtures need no asset.

MSF inspection supports glTF/GLB, including JSON glTF aliases json/gltf2. Geometry is a separate limited position/morph/four-influence LBS/animation implementation. Inventories of VRM, Roblox or other interfaces do not implement their loaders or establish geometry/material/visual equivalence.

Sources: mapping.py, snapshot.py, and shared reference.

Practical authoring

Edit, regenerate, check, then qualify

Choose the reviewed dependency and edit the authoritative TOML. Generated artifacts and readable reports are review surfaces. The commands below are suggested workflow steps; they were not executed for this report.

  2. Install MSF Tools at the commit recorded in evidence/tooling.lock.json.
  3. Run regeneration, review every changed output, then run the default no-write drift check.
  4. Run the tests with the same tools; retain domain and capture limits.

Installed package

python3 -B check.py --write
python3 -B check.py
python3 -B -m unittest discover -s tests

check.py uses python -m msf_tools with the running interpreter’s installed import environment. It does not install or fetch anything.

--write regenerates; default invocation checks drift. The wrapper first runs the shared pack/CSV/coverage/checksum check. Only on success does it run the RCEF presentation exporter with the same write/check mode. It does not run the tests. Shared generated output checks may reject unexpected entries.

JSON has sorted object keys, indent=2, UTF-8 and final LF; numbers are finite and negative zero is normalized. Arrays retain authoring order. CSV has UTF-8, LF and minimal standard quoting. All shared bytes are rendered before publication. Each file replacement is atomic; the generated and presentation sets are not one transaction. After failure, inspect all outputs and rerun the check.

Independent acceptance remains explicit

What still needs qualification

Implemented parsing and arithmetic rules are reviewable in source. A successful rendering check proves matching generated bytes within that run. Full acceptance and domain claims require their own evidence.

No fresh qualification is claimed. The tests exercise the shared runtime with the selected tools. Native backend tests and installed/release-wheel admission are separate.

Review checklist

  • Recompute all TOML counts, unique IDs, exact references and array order; compare merged data to the pack. Keep selected-interface counts separate from actual rows.
  • Verify independent numeric goldens for ARKit identity, affine low/mid/high and ordered bilateral pairs. Require approximation opt-in and preserve both authored losses.
  • Exercise missing/false/nonboolean validity, missing required inputs, extra/non-source channels, nonfinite/out-of-domain values and a failing frame in a multi-frame batch. Require no evaluated value on error.
  • Require unresolved MediaPipe→ARKit execution to refuse. Review calibration, native neutral/default, raw storage validity and directional assumptions without inferring inverse or anatomical equivalence.
  • Run the default drift check and the tests with a reviewed tools origin. Review native, package, device/capture and physiological gates separately.
  • Independently test this HTML offline, at narrow widths, in print and with JavaScript disabled. Tab through selectors, search, reset, sliders and approximation checkbox; check screen-reader announcements and numeric/state behavior.
  • Verify relative links after adoption under RCEF/docs, with msf-tools as a sibling. Review licensing and attribution.
