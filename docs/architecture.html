Eight steps

Architecture and ownership

check.py runs two RCEF checks first. Then msf-character-tools discovers, validates and compiles the pack. After that there are two separate paths: one for runtime and one for exported files. The map and evaluate commands build the Pack again from TOML. The readable reports read the generated pack JSON directly.

RCEF supplies

Data, checks and review files

Pack metadata, provider and canonical signals, intermediate signals, profiles, evidence, directional maps and original numerical fixtures. Calibration records and the FREEZES ledger. The check.py launcher, the report exporter, the calibration tools and the tests. RCEF declares meaning and provenance. It does not implement the shared scalar algorithms.

msf-character-tools implements

Check, compile and evaluate

Authoring discovery and strict validation, pack compilation, map compilation and evaluation, and asset inspection and sidecar binding. RCEF locks msf-character-tools 0.5.0 and installs its release wheels. The locked commit is in tooling.lock.json. An evaluation report, with diagnostics and losses, is not the same as a readable Markdown or CSV report.

Before msf-character-tools runs

What check.py does, and calibration records

check.py runs these steps in order. It stops at the first failure.

  1. Locked msf-character-tools. It reads tooling.lock.json, which is lock format 2. The lock records the msf-character-tools commit and version, and one entry per wheel tag. Each entry has the wheel’s SHA-256 (when known) and a SHA-256 for every file in the installed msf_character_tools package. check.py refuses unless the package was built from the locked commit, its wheel tag has an entry, and every file matches both its RECORD entry and the lock. It also refuses if msf_character_tools would be imported from a different place.
  2. Calibration records. It reads every *.cal record in calibration/ and the freeze ledger calibration/FREEZES. Each record must match the record format. Its frozen hash must be the latest one in the ledger for its id. A mapping that cites a record (evidence id calibration.<id>) must use piecewise_linear with exactly the record’s frozen knots. Every held-out cell for its input channel must pass. This step does not use msf-character-tools. No mapping in data 0.5.0 cites a record.
  3. Shared outputs. It runs python -B -P -m msf_character_tools check on the checkout, with an empty bytecode cache. With --write it regenerates the pack, the CSV, coverage and checksums. Without it, it checks that they have not changed.
  4. Readable reports. If step 3 passes, it runs the report exporter with the same write or check choice.

check.py --update-lock records the installed msf-character-tools in the lock and exits. It keeps the old lock as tooling.lock.previous.json when the commit or version changes.

Two calibration records

A calibration record is a software-only fit, made from renders of example rigs. Its frozen part (everything except cells) is hashed. The hash is written to calibration/FREEZES and committed before the held-out run. The held-out seeds come from that hash.

  • mediapipe.ict-response: a negative result. 25 of MediaPipe’s 51 ARKit-named scores could be fitted. None passed on held-out data.
  • rig-gains.ict-rocketbox-female: 3 of 51 ARKit shapes pass (browInnerUp, cheekSquintLeft and cheekSquintRight). 48 fail, and they are published as negative results.

The held-out provenance check

The calibration tools run the held-out step. Before they render anything, provenance.py checks two things. The record’s code_commit must be in the checkout’s history. No file that the run imports can have changed since that commit.

The tools also check that every cached input has the SHA-256 that the record pins, and that the installed msf-character-tools passes the lock check. k3_heldout.py also requires the renderer binary that the record names.

check.py cannot see Git history. Reviewers check that the ledger line was committed before the results.

Interactive reference

Explore a step or a file role

Folders only organize the files. The top-level keys in each parsed file decide the record kinds. Select a step to read about it. Select a role to filter the complete list of authoritative files. The filter does not change what the parser does.

1 · Check the locked msf-character-tools

check.py reads tooling.lock.json (lock format 2). It compares the installed package with the locked commit, the entry for its wheel tag, and a SHA-256 for every package file. If anything is different, it stops. It does not install or download anything.

Source: check.py. The Markdown guide gives the full rules.

2 · Check the calibration records

check.py reads each *.cal record and the FREEZES ledger. The frozen hash of each record must be the latest ledger line for its id. A mapping that cites a record must use piecewise_linear with the record’s frozen knots, and all held-out cells for its channel must pass. No mapping in data 0.5.0 cites a record.

Source: calibration/README.md and check.py. This step does not use msf-character-tools.

3 · Discover TOML, read it strictly and merge the arrays

A directory must contain pack.toml. msf-character-tools walks the tree and includes every file name that ends in lowercase .toml. It skips names that start with . and directories named generated. It refuses symlinks, and it sorts all paths before it merges them. Arrays are added in file order. A repeated metadata key is refused.

Parsing is strict UTF-8 with tomllib.loads. The validator refuses unknown keys, missing keys, invalid enums, duplicate IDs, references to records that do not exist, and invalid numbers or domains. Valid TOML syntax alone does not make a valid pack. Well-formed unresolved entries stay in the inventory.

Source: load_authoring, authoring_files, _read_fragment and validate_authoring.

4 · Compile the validated document

compile_pack takes a validated document, not a raw dictionary. The Pack holds the same document, which cannot change, and the SHA-256 of its canonical bytes. This step does not compile a map or bind an asset.

Source: compile_pack and Pack.

5 · Write and check deterministic bytes

msf-character-tools writes rcef.pack.json, rcef_mapping.csv, coverage.json and SHA256SUMS. The CSV is a signal and profile membership matrix. It is not a table of mappings. The default check compares bytes. --write regenerates.

Source: the check command in cli.py. Each file is replaced atomically. The set of files is not one transaction.

6 · Compile a map and evaluate frames

Choose a map, an in-memory Pack, and explicit source and target snapshots. The map and evaluate commands build that Pack from TOML. They do not read the generated files. Compilation checks the graph, the endpoint types, domains, calibration and evidence, and the approximation choice. Evaluation needs exact frame objects: non-negative seconds, finite in-domain values and explicit boolean validity. If any frame has an error, the Result has no value.

Source: profile_snapshot, compile_mapping and evaluate_mapping. There is no clamping, no neutral substitution and no hidden cross-provider conversion.

7 · Show the authored facts from the pack

RCEF exports Markdown and CSV pairs for the inventory, the mappings and the canonical correspondence. They include unresolved and excluded records. A dash means that there is no authored mapping. The Markdown reports record the SHA-256 of the pack they read. reports/SHA256SUMS holds the hashes of the six report files.

Source: export_reports.py. The exporter does not run the evaluator or make geometry.

8 · Check correctness and scope independently

Run the drift check and the tests with the locked msf-character-tools. On these repositories, scripts/ci_local.sh runs both on Python 3.11 and 3.12. Native backend tests, capture validity and physiological calibration are separate questions.

Source: tests and CONTRIBUTING. This page does not report a test run.

Calibration tools · freeze, then run the held-out step

To change a calibration record or add one, freeze it first. Commit the ledger line. Then run the held-out step. Before it renders, provenance.py checks the record’s code_commit and the files that the run imports. The tools also check the cached input hashes and the lock.

Source: tools/calibration/README.md. Reviewers check that the ledger line came before the results.

Actual schema · no inferred keys

Authoring TOML correctly

The complete metadata in pack.toml

schema_version = "1.0"
data_version = "0.5.0"
operator_version = "1.1"
id = "rcef.parity"
license = "CC-BY-SA-4.0"

There is no key that lists fragment files. Directory loading supplies the four merged arrays: signals, profiles, mappings and evidence. A single-file input must supply them itself.

msf-character-tools 0.5.0 accepts schema versions “1.0” and “1.1”, and operator versions “1.0” and “1.1”. Operators 1.1 add piecewise_linear. A mapping that uses it under operators 1.0 is refused. Schema 1.1 adds the evidence status calibrated_software. RCEF uses schema 1.0. The data version has its own number. It must be a semantic version: three numbers, with an optional prerelease suffix.

Arrays and nested tables mean different things

[[signals]] adds a record. [signals] makes an object instead, and it fails the array check. domain = { min = 0.0, max = 1.0 } is an inline nested object.

[signals.domain] describes the domain of the latest signal. Put the signal’s own fields before you open nested tables. rules = [{...}, {...}] and repeated [[mappings.rules]] tables are two ways to write the mappings of a map. [mappings.rules.operator] is the operator of the latest mapping.

Dots in keys make nested objects. Dots in an ID string are only characters: "arkit.coefficient.eyeBlinkLeft" is one exact ID.

References are exact and case sensitive. IDs are not trimmed or normalized. Signal, profile, map and evidence IDs are unique within their category. Mapping IDs are unique across all maps. Profile memberships, mapping inputs and outputs, and evidence references must name existing records. Names, labels, sides or similar anatomy never create aliases or mappings.

Types, status and order that matter while editing
  • Dispositions are mapped / unsupported / unresolved / excluded. Evidence statuses are verified_current / proposed / unresolved. Status, disposition and mapping quality answer separate questions.
  • Units and calibration are required non-blank strings. Neutral and native default are each optional, finite and inside the domain. Neither one is a fallback.
  • Validity is a boolean or a non-blank description. Confidence is a non-blank description or a number in [0,1]. Time is a description. Coupling is a description or an array of unique descriptions. These descriptions do not run.
  • Inventory details go in metadata. Unknown structural keys, repeated entries in reference arrays and references to missing records fail.
  • File order and the order of each array are kept. JSON sorts object keys, not arrays. Profile columns follow profile order. Weighted-sum weights follow input order. Compilation repeatedly takes all mappings whose inputs are ready, in authored order. So dependencies run first, and authored order is kept within each batch. Independent mappings in different batches can change their relative order.
  • Strict TOML parsing comes first, then JSON-compatibility and number checks. TOML dates and times, booleans as scalars, NaN and infinity are refused. Text is never executed.
  • A new lowercase TOML file anywhere in the discovered tree is read, including an example under docs/. Keep examples in Markdown code fences or outside the tree.

Exact definitions: validate_signal, validate_rule and validate_authoring. Full field tables: Markdown guide.

Identity is exactly y = x. Affine does a checked binary64 multiply, then an add. A weighted sum starts at 0.0 and adds checked products in input order. It does not normalize the weights. piecewise_linear finds the segment that holds x and interpolates linearly. Then it keeps the result between that segment’s two y values, so rounding cannot break monotonicity. Non-finite results, and non-zero products or quotients that underflow to zero, are refused. Inputs are not clamped, and there is no fused multiply-add.

Keep declarations apart from samples

Runtime admission and validity

Map compilation is stricter than inventory validation

A well-formed unresolved record can stay in a pack. A requested map needs mapped signals and mappings, non-empty evidence of its own, and compatible endpoint types, units, domains and calibration. A verified_current mapping needs verified_current endpoints. A proposed mapping can use verified_current or proposed endpoints. Evidence references follow the same pattern. Unresolved evidence anywhere in the map refuses execution.

An identity mapping also needs the same neutral, side and coupling on both ends. A non-identity mapping with a changed basis, or with a declared approximation or loss, needs written assumptions. The approximation opt-in is checked separately for all operators. The first and last knots of a piecewise_linear mapping must be its input’s domain bounds. Compilation refuses unknown channels, more than one writer for a signal, an output that is also a source channel, and dependency cycles. Intermediate outputs can stay virtual. Terminal outputs must be in the target snapshot.

The unresolved MediaPipe → ARKit blink mapping stays as a recorded ambiguity. Its identity operator does not admit it. The approximation opt-in does not bypass the evidence or type checks.

Every frame supplies validity

Frames contain exactly timestamp, values and validity. The timestamp is finite, non-negative seconds. Every supplied value has a boolean validity. Every external input that the map needs must be supplied.

  • A value without validity, or validity that is not a boolean: E_VALIDITY.
  • A required value and its validity both absent: E_MISSING_SAMPLE.
  • A finite in-domain value with validity false: E_INVALID_SAMPLE, even when the number is equal to neutral.
  • An unknown or non-source channel: E_SAMPLE_REFERENCE.
  • Non-finite, boolean or out-of-domain values are refused. Values are checked before and after each operator.

If any frame has an error, the whole Result has no value. Valid frames keep their order, and each written output has validity true. There is no smoothing, no neutral or default substitution and no hidden resampling.

Authoring a map and binding an asset are separate

profile_snapshot(pack, id) makes typed virtual channels from a named profile. A mapping connects signal IDs with arithmetic. An asset binding connects a signal to a morph target in an asset. Names alone never bind geometry.

binding fields: id, value_type, units, domain, calibration, ref
ref fields: asset_sha256, locator, node, mesh, target
optional ref field: resource_sha256
locator must agree with /nodes/{node}/weights/{target}
sidecar: schema_version, asset_sha256, resource_hashes, bindings
optional sidecar field: metadata

Sidecar reuse checks the exact asset hash and the hashes of the resources it reads. annotate_asset makes a sidecar and does not change the asset bytes. Asset-based CLI mapping needs explicit sidecars. Profile-based fixtures need no asset.

msf-character-tools 0.5.0 inspects glTF and GLB (gltf, glb, and the aliases gltf2 and json). It also reads the source formats usd, usda, usdc, usdz and fbx through its source adapters. Bindings on those use a source_locator. RCEF’s face examples load Rocketbox FBX files this way; msf-character-tools 0.5.0 reads FBX with no extra package. The geometry code has a limited scope: positions, morphs, linear blend skinning and animation. RCEF’s inventories for VRM, Roblox and other surfaces do not add loaders for those formats. They do not prove geometry, material or visual equivalence.

Sources: mapping.py, snapshot.py and the shared reference.

check.py runs the installed msf_character_tools with the running interpreter, after the lock check. On these repositories, scripts/ci_local.sh runs check.py and the tests on Python 3.11 and 3.12.

--write regenerates; the default run checks for drift. check.py first checks the lock and the calibration records. Then it runs the shared pack, CSV, coverage and checksum check. Only if that passes does it run the RCEF report exporter with the same choice. It does not run the tests.

JSON has sorted object keys, indent 2, UTF-8 and a final LF. Numbers are finite, and negative zero is normalized. Arrays keep the authoring order. CSV has UTF-8, LF and minimal standard quoting. All shared bytes are rendered before any file is written. Each file is replaced atomically, but the generated files and the report files are not replaced in one transaction. After a failure, review all outputs and run the check again.

Independent acceptance stays explicit

What still needs qualification

The parsing and arithmetic rules can be reviewed in the source. A passing check shows matching generated bytes in that run. Full acceptance and domain claims need their own evidence.

This page does not claim a fresh qualification. The tests exercise the shared runtime with the locked msf-character-tools. Native backend tests are separate.

Review checklist

  • Recompute the counts from all 39 TOML files, the unique IDs, the references and the array order. Compare the merged data with the pack. Count memberships apart from distinct signals and from selected-interface metadata.
  • Check the independent expected values: identity 0.25, affine -1/0/1 → 0/0.5/1, the ordered bilateral pairs, and the gaze splits. Require the approximation opt-in, and keep every authored loss.
  • Try a missing value or validity, false or non-boolean validity, missing required inputs, extra or non-source channels, non-finite or out-of-domain values, and one failing frame in a batch. Require no Result value on error.
  • Confirm that the unresolved MediaPipe → ARKit mapping refuses to run. Keep evidence status, disposition and quality apart. Do not infer inverse or cross-provider mappings from names.
  • Run the no-write drift check and the tests. check.py first checks the installed msf-character-tools against the lock, and then the calibration records against FREEZES. Test the native backend separately.
  • Test this HTML offline, at narrow widths, in print and with JavaScript turned off. Tab through the selectors, search, reset, sliders and the approximation checkbox. Check the screen-reader announcements and the displayed numbers.
  • Check relative links under RCEF/docs, with an msf-character-tools checkout at the locked commit next to RCEF. Check the licensing and attribution.
