The source routes come from the Godot OpenXR vendors plugin (FB2 weight → Godot shape, MIT) and Godot's
face-modifier name table (Godot shape → ARKit name, MIT). Where Godot has no route, VRCFaceTracking's
parameter code is used.

RCEF translates FB2 to ARKit through its canonical expression set: an in-map (FB2 → canonical) and an
out-map (canonical → ARKit). The two hops are composed exactly, and the composed weights are compared
exactly. The "RCEF maps" column names the two maps.

RCEF translates 52 ARKit coefficients from FB2. Weight disagreements with Godot: 0. Without a Godot route: 1. Godot translates 0 more that RCEF does not yet.

## Every difference from Godot

- **browInnerUp** (`fb2.to_rcef_expression` → `rcef_expression.to_arkit`): Godot has no route; RCEF follows VRCFT's average (0.5·INNER_BROW_RAISER_L + 0.5·INNER_BROW_RAISER_R).
- **mouthClose** (meaning, not weights): FB2 LIPS_TOWARD closes the lips "regardless of the position of the jaw"; VRCFT's Unified Expressions table defines MouthClosed relative to JawOpen (`vrcft_docs_shapes`), and SRanipal requires Jaw_Open to be inactive. Godot and VRCFT both copy the value directly, as RCEF does. For ARKit, RCEF's audit leaves the jaw relation unresolved: Apple's text says that mouthClose does not depend on the jaw, but RCEF's own calibration record reads it together with jawOpen (`arkit_mouthclose_jaw_unresolved`).
- **mouthShrugUpper** (meaning, not weights): ICT-FaceKit relates mouthShrugUpper to FACS AU10 (upper lip raiser), while Godot, VRCFT and RCEF use FB2 CHIN_RAISER_T; FB2 has separate UPPER_LIP_RAISER_L/R weights.
- **jawOpen** (meaning, not weights): ICT-FaceKit relates jawOpen to FACS AU27 (mouth stretch); FB2 JAW_DROP is the jaw drop.
- **mouthUpperUpLeft, mouthUpperUpRight** (meaning, not weights): ICT-FaceKit relates mouthUpperUp to FACS AU11 (nasolabial deepener); Godot, VRCFT and RCEF use FB2 UPPER_LIP_RAISER, named after AU10.
- **cheekPuff** (meaning, not weights): ICT-FaceKit relates cheekPuff to FACS AU33 (cheek blow); RCEF's canonical cheek puff has AU34 (puff), so the ICT crosswalk does not carry over for the FACS code (`ict_au33_cheek_blow`).
- **eyeBlinkLeft, eyeBlinkRight** (meaning, not weights): ICT-FaceKit relates eyeBlink to FACS AU45 (blink); RCEF's canonical eye closure has AU43 (eyes closed), so the ICT crosswalk does not carry over for the FACS code (`ict_au45_blink`).
- **mouthSmileLeft, mouthSmileRight** (meaning, not weights): Unified Expressions MouthSmile blends corner pull and corner slant; FB2 has no slant, and Godot sets it to zero.
- **eyeLookIn/Out** (meaning, not weights): VRCFT's Meta Movement and overview tables name FB2 weights EYES_LOOK_IN/OUT_*, which do not exist in the OpenXR registry, so they cannot settle the sides. Godot routes the FB2 values as RCEF does; ICT-FaceKit names ARKit shapes only; the FB2 figures (`xr_fb2_fig_eyes_look_left_l`) show the subject's own side.
